# BUG-009 — One zero-amount row fails the whole statement with “Jurnal minimal dua baris”

| | |
|---|---|
| **Severity** | Low |
| **Status** | **Fixed** (branch `task/fix-qa-bugs`) |
| **Area** | Impor Mutasi |
| **Test cases** | E16 |

## Steps to reproduce
1. Upload a BRI-format CSV containing a row with MUTASI_DEBET 0.00 and MUTASI_KREDIT 0.00.

## Expected
The zero line is skipped (or flagged with its row number); other rows import.

## Actual
Nothing imports; toast *“Jurnal minimal dua baris”* (an internal ledger message, no row reference).

## Root cause
A zero line produces a journal with no non-zero lines; `postJournal` throws `Jurnal minimal dua baris`.

## Impact
Rare but confusing; blocks the month.

## Suggested fix (original)
Drop or warn on zero-amount rows in the parser with a note naming the row.

## Evidence

![E16-zero-amount-row.jpg](../screenshots/E16-zero-amount-row.jpg)

## Fix applied

`importStatement` leaves out rows whose amount is zero, with the note *“N baris bernilai nol dilewati (baris …)”*; a file with only zero rows says so.

**Regression guard:** `tests/db/import-twin-rows.test.ts`.

**Re-verified in the browser:** case `VF-009` in [results-table.md](../results-table.md).
