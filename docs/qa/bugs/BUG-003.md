# BUG-003 — `250,000` is read as Rp 250 (Western thousands separator silently shrinks the amount 1,000×)

| | |
|---|---|
| **Severity** | High |
| **Status** | **Fixed** (branch `task/fix-qa-bugs`) |
| **Area** | All typed amounts (Jurnal, Saldo Awal, Faktur, Aset, Sewa…) |
| **Test cases** | K2 · N5c · unit probe |

## Steps to reproduce
1. Open *Jurnal Penyesuaian*.
2. Type `250,000` in Debit and in Kredit; leave the field.
3. Click *Simpan jurnal*.

## Expected
Either Rp 250.000, or a refusal explaining the format.

## Actual
The field re-displays `250`, the journal is *Seimbang* and saves **Rp 250**. `parseMoney("1,000")` → 1 and `parseMoney("250,000")` → 250 (probe output in the report). Other forms using `parseMoney` behave the same.

## Root cause
`lib/money.ts:149-155`: `^(\d{1,3}(\.\d{3})+|\d+)(,(\d+))?$` accepts `250,000` as integer 250 with a decimal part `000`, and zero decimals are allowed for IDR.

## Impact
An accountant pasting figures from Excel with an English locale (very common) books amounts 1,000× too small, and both sides of a journal shrink equally so it still balances — no control catches it.

## Suggested fix (original)
For exponent-0 currencies, reject a lone comma group of exactly three digits (`^\d{1,3},\d{3}(,\d{3})*$`) with the existing *“tulis dengan titik ribuan”* hint, or auto-detect US thousands when a comma is followed by exactly three digits and no other separator. Add unit cases for `1,000`, `250,000`, `1,000,000`.

![K2-western-separators.jpg](../screenshots/K2-western-separators.jpg)

## Fix applied

`parseMoney` (`lib/money.ts`) refuses a comma followed by exactly three digits when it cannot be a real fraction (any such group for IDR/JPY, all-zero groups for two-decimal currencies) with *“bisa dibaca ribuan atau desimal. Tulis ribuan dengan titik”*. Indonesian notation and real decimals (`12,5`) are unchanged; `1,005` in SGD keeps its existing “too many decimals” message.

**Regression guard:** `tests/unit/amount-input.test.ts`.

**Re-verified in the browser:** case `VF-003` in [results-table.md](../results-table.md).
