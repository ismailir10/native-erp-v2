# BUG-001 — Import fails for identical same-day lines when the statement has no running-balance column

| | |
|---|---|
| **Severity** | Blocker |
| **Status** | FIXED in this PR |
| **Area** | Impor Mutasi |
| **Test cases** | E14 (before) · E14-fixed (after) |

## Steps to reproduce
1. Create a client with one BCA account.
2. Upload a CSV with a `SALDO AWAL` row and **no Saldo column**, containing two identical rows, e.g. `02/08/2026;BIAYA ADM;15.000,00;0,00;` twice, plus one other row.
3. Click *Proses mutasi*.

## Expected
All three lines import (two Rp 15.000 bank fees on one day are two real bank lines).

## Actual
Nothing imports. The user sees only the toast *“Terjadi kesalahan tak terduga. Coba lagi.”* The server log shows `Unique constraint failed on BankTransaction_bankAccountId_hash_key` (P2002).

## Root cause
`rowHash` (`lib/import/normalize.ts`) is `sha1(date|amount|description|balance)`. Without a balance, identical rows hash identically and the unique index `(bankAccountId, hash)` rejects the second one, rolling back the whole transaction.

## Impact
Bank statements from CMS/e-banking exports without a balance column cannot be imported whenever the same fee, QRIS settlement, or transfer amount repeats on one day — common. No workaround except editing the file. Whole month blocked, no explanation.

## Suggested fix
**Done:** `rowHashes()` gives the nth identical row an ordinal-suffixed hash; the first keeps its plain hash, so previously imported data and re-upload dedupe are unchanged. Regression tests: `tests/db/import-twin-rows.test.ts` (3, fail before / pass after) and `tests/unit/row-hashes.test.ts` (3). Verified again in the browser (E14-fixed).
