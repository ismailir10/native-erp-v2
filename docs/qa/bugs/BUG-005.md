# BUG-005 — Cross-rate `0.745` is stored as 745 (and `1.085` as 1085)

| | |
|---|---|
| **Severity** | Medium |
| **Status** | Open |
| **Area** | Kurs (Pengaturan klien) |
| **Test cases** | Q4 (fails) · Q3a–Q3f (USD→IDR inputs pass) |

## Steps to reproduce
1. On a client with a USD entity open *Kurs*.
2. From SGD to USD, date 31 Aug 2026, Kurs `0.745`, *Simpan kurs*.

## Expected
Stored rate 0.745.

## Actual
Toast *“Kurs SGD→USD disimpan”*; stored rate **745**. `normalizeRateInput("105.234")` → 105234 and `("0.745")` → `"0745"`.

## Root cause
`lib/fx/currency.ts:111-114`: any `d{1,3}.ddd` is treated as a thousands group, even when it starts with `0` or the pair's magnitude is below 1000.

## Impact
Translation of a foreign entity (Gabungan Grup) and FX revaluation use a rate that is 1,000× wrong. USD→IDR style rates (16.250) are correct; the risk is cross-rates and JPY→IDR-like quotes typed with a decimal point.

## Suggested fix
Treat a leading `0` group as a decimal (`0.745`); and for 3-digit fractions compare against the previous rate for the pair or ask for confirmation when the result differs by > 100×. Add unit cases for `0.745`, `1.085`, `105.234`.
