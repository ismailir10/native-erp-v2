# Two decks: for accounting firms, and for companies

## Context
The public deck (`/deck`, cycle `2026-10-03-product-deck.md`) is one 14-slide pitch written before the three-stage spine
([ADR 0014](../adrs/0014-three-stage-spine.md)), Papan kantor, Kelengkapan data, the client upload link, Pajak Masa, Ekualisasi PPN
and Tanya Buku existed. It also breaks the repo's own look rules (aurora background, shiny and gradient text, glow; see
`ui-rules` → "No AI-slop"). The owner asked for a new version split by audience:

1. **Accounting firms managing several clients** — the buyer in ADR 0014.
2. **Companies that need accounting software** — a buyer ADR 0014 only reaches *through* firms. See Assumption 1.

Brief from the owner: simple, rich in visuals and illustrations that carry the product's value, no nonsense, no typical AI-slop,
Bahasa Indonesia, reviewed and iterated before it is shown.

## Spec
Approval: the owner's brief, given in-session, is the spec. It names audience, tone, language and the quality bar. No new
dependency, schema or app route is added.

- [x] **Two decks, static, public, no login:** `/deck/kantor` (firms) and `/deck/perusahaan` (companies); `/deck` is a two-link chooser.
- [x] **Look: Stripe-like restraint, owner decision.** First built to the app's `ui-rules` (sharp corners, hairlines, no gradients), then the owner
  asked for one sans-serif, "Stripe simplicity" and React Bits illustrations. So the decks deliberately depart from `ui-rules` (soft cards with
  shadows, rounded corners, a quiet gradient mesh on cover and close, gradient on one headline phrase); the app itself is untouched. One family
  throughout: Plus Jakarta Sans (designed in Jakarta; OFL, vendored in `public/deck/fonts`). No emoji, no stock art, no hype copy.
- [x] **Motion = vanilla ports in the manner of React Bits** (the decks are static HTML, so no React): CountUp on key figures, AnimatedList-style
  staggered entrances, a fanned file Stack, DotGrid and drifting mesh on navy slides, SpotlightCard hover, BorderBeam on the key card, CheckDraw on
  status ticks, packets travelling through the transfer bridge and the posting gate. Licence text copied to `public/deck/REACT-BITS-LICENSE.txt`
  (MIT + Commons Clause, as in `components/motion/`). Everything is skipped in print/PDF, in flow mode and under `prefers-reduced-motion`.
- [x] **Every slide carries one picture that shows the mechanism:** product mockups in HTML/CSS and diagrams in inline SVG, built from
  synthetic data and labelled *data demo sintetis*. No stock art, no real client, no bank logos.
- [x] **Honest content:** only what Buku does today (README, ADRs, cycle docs). No invented metrics, customers, prices or time-saved
  figures. Each deck has a slide that says what Buku does not do. The success measure offered is the one Buku itself records
  (`npm run close:timeline`: file received → locked → report sent).
- [x] **Presenting and reading:** 16:9 stage with arrows / space / swipe / `#n` deep links / `F`; below 900 px or in portrait it reads as one
  scroll. `@media print` gives one slide per landscape page so a PDF can be exported.
- [x] `/deck` stays public and same-origin only (CSP unchanged).

**Non-goals:** app code, pricing, contact forms, analytics, a CMS, bilingual copy, naming or ranking competitors, committing PDFs.

**Assumptions** (owner to confirm):
1. ADR 0014 default *"the buyer is the accounting firm, and SMEs are reached through firms"* is not reversed. The company deck therefore
   sells what a company gets from Buku today — books closed from its own statements, by its in-house accountant or its firm — and says
   plainly that Buku is not an invoicing, POS or payroll tool. A company reaches Buku only by invitation, as now.
2. The old product deck is replaced, not kept beside the new ones. `docs/cycles/2026-10-03-product-deck.md` remains as history.
3. Right Jet's logo, email and colours are still unavailable: text wordmark and `right-jet.com` only.
4. Names in mockups come from the synthetic demo firm (*KJA Demo & Rekan*, Grup Ayam Nusantara, CV Sinar Retail) plus clearly fictional
   extras. Accurate and Jurnal are named only as sources Buku can import from, as the README does.

## Implementation
- `public/deck/{index.html,kantor.html,perusahaan.html,deck.css,deck.js}`; `next.config.ts` rewrites `/deck/kantor` and `/deck/perusahaan`.
  The decks are generated from small scratch templates and committed as plain static HTML, as the old deck was; there is no build step in the repo.
- **Engine:** 16:9 stage where 1rem = 1/160 of the slide (everything scales with the window), one slide at a time with arrows, space, swipe, `#n`,
  `F`; below 900 px or in portrait it becomes one scroll (`html.flow` rules); `@media print` gives one landscape page per slide (13 pages each).
- **Firm deck (13):** cover · problem (a 6 × 4 × 12 = 288 files calculation) · Papan kantor + Tanya Buku · three stages · balance proof ·
  Kelengkapan data + client upload link · review queue + what goes to AI · trace · close controls with a disabled lock · one report page + three
  packs · PT + owner group and Kertas Kerja Gabungan · single posting gate + what does not exist · how to start.
- **Company deck (13):** cover · owner questions · four steps · where Buku sits among other tools · trace (an expense, not a sale) · close controls ·
  Tanya Buku · report packs · Pajak Masa + Ekualisasi PPN · group · data and AI · fit / no fit · how to start.
- **Typography, three rounds.** Inter + uppercase mono eyebrows read as generic ("still looks really like AI"); a serif + IBM Plex pairing followed;
  the owner then asked for sans-serif and Stripe-like simplicity, so the final system is Plus Jakarta Sans only, sentence-case labels, soft cards,
  larger text and fewer words per slide (long footnotes and secondary lists cut; honesty caveats kept).
- **Illustration upgrades (v3):** a fanned stack of client files and a 6 × 4 × 12 = 288 counter on the problem slide, staggered board and proof rows
  that verify one by one, an amount bridge with a travelling packet, a posting gate with packets, one rendered report page in the report slide,
  mesh + dot grid on the cover and closing slides, real thumbnails on the chooser.

## Verification
- Every slide of both decks screenshot-reviewed at 1440×900 and 390×844 after each round; an automatic check (`.s-body` overflow, content
  below the footer, content past the right margin) is clean for the firm deck and for 12 of 13 company slides at 1600×900; the remaining flagged ones
  (company slides 6 and 10) are a 60 px phantom from a zero-opacity element and render correctly in the screenshots.
- Mobile: `scrollWidth == innerWidth` on both decks; wide tables scroll inside their own card.
- Print: Chromium PDF export, 13 pages per deck, fonts embedded, all figures at their final values (`beforeprint` restores any count-up in flight).
- Motion verified by capturing mid-animation frames (staggered rows, counting numbers) as well as the settled state.
- No console errors; only same-origin requests (fonts, css, js); chooser thumbnails are same-origin iframes of each deck's cover.
- **Independent review (two agents, read-only):**
  - *Copy and claims audit* found: "only humans post" (rules, memory and transfer pairs post directly — fixed to say AI never posts and only the
    accountant closes and locks); "AI sorts files" (not built — removed); review mockup listing rule/memory rows that would already be posted
    (now only AI/low-confidence rows); "closed by passing controls" (a *Perlu dicek* control closes with a note — headline now "lolos atau dijelaskan");
    "every number traces to a bank row" (adjusting entries trace to their journal — narrowed); "laporan siap", "bank apa pun", "kolom apa pun"
    (softened); demo numbers that disagreed across slides (account ····5566 vs ····3344, PT Ayam vs CV Sinar P&L, an invented journal number
    J-0142, 1999 control green while 5 lines wait in review — all aligned); "Terkirim" means first download after lock (stated on the board
    slide, the start slide says *diunduh*); the company deck implied owners log in (now says access is Admin/Akuntan by invitation); the AI data slide
    implied one line leaves Buku (now lists the other AI uses and the third-party provider). Wording: "dikode", "mati secara bawaan",
    "gerbang", "dinilai terhadap", empty eyebrows like "Jujur soal batas".
  - *Visual critique* found: headline top position jumping between slides (now anchored), a mockup that contradicted its headline (close slide:
    two open findings but a live button — now disabled and says what holds it), table-of-contents report slide (now one rendered report page),
    skeleton-bar problem slide (now the calculation), tangled group diagram (now one amount bridge), tiny labels (raised), misaligned columns on
    "where Buku sits", chooser without thumbnails, five company slides copied from the firm deck (trace now an expense; report slide
    different hero/order; Tanya Buku rebuilt as a chat with input and a large answer).
- **Not run:** `npm run lint/typecheck/test/build/verify:books/test:e2e` (sandbox cannot `npm ci`: `cdn.sheetjs.com` is blocked; no app, ledger or report
  code changed; CI runs them). The Next rewrites were not exercised by a dev server; they copy the existing `/deck` → `/deck/index.html` pattern.
- **Open for the owner:** (1) confirm the company-deck framing against ADR 0014; (2) the 288-files calculation is an illustration for a six-client firm,
  not a measurement; (3) Right Jet logo/colours/contact still missing.
