# Invitation and reset links from the default email template

## Context
On 2026-10-10 an owner invited a new organisation owner from the backoffice. The hosted project still sends Supabase's default
email template (Buku's templates are not pushed yet; `auth:config --apply` is an open owner action). Its link verifies on the
auth server and then sends the browser to Buku's link page with the session in the address fragment (`#access_token=…`). The link
page only understands Buku's own template (`?token_hash=…&type=…`), so it showed *Tautan tidak berlaku* to someone whose link had
just worked: the account was confirmed and signed in, but the person never reached the password page. A password reset takes the
same path, so it fails the same way. Who feels it: every invited member and every reset until the templates are pushed, and
anyone holding an email sent before that.

## Decisions
- The link page accepts both link shapes. Buku's template stays the preferred one (scanner-safe: a GET consumes nothing); the
  fragment shape is already consumed by the auth server before the page loads, so forwarding it loses no safety. (Owner: "go
  ahead with the callback fix", 2026-10-10.)
- The fragment is handed to the existing password page, which already adopts a session from the fragment and removes it from
  the address bar. No new page.

## Acceptance criteria
- [x] A default-template invitation link opens Buku's password page; after *Simpan dan masuk* the person is in their workspace.
- [x] A default-template reset link does the same.
- [x] A fragment carrying an auth error (expired, used) shows the Bahasa expired/invalid message with *Kirim tautan baru*, as before.
- [x] Buku-template links (`token_hash`) behave exactly as before: GET shows *Lanjutkan*, nothing is consumed until it is pressed.
- [x] The error page never flashes before the forward, and the session never stays in the address bar.

## Verify flows
1. Invited member (local stack): an invitation link generated in the default shape → lands on *Atur kata sandi* → set a password
   → Beranda of their organisation.
2. Reset (edge): a recovery link in the default shape → *Atur kata sandi* → new password works at /login.
3. Error case: `/auth/callback#error=access_denied&error_code=otp_expired` → *Tautan sudah kedaluwarsa* page with *Kirim tautan baru*.
4. Regression: the existing captured-mail flow (`e2e/auth-links.spec.ts`) still passes.

## UX notes
While the page decides (a fraction of a second), it shows the neutral *Membuka tautan…* state, never the error.

## Test seams
- Unit: the pure decision "where does this fragment go" (session → password page, error → error page, nothing → error page).
- e2e: an invite and a recovery link generated by the local auth server's admin API in the default shape, followed in the browser.

## Non-goals
Pushing the templates to the hosted project (owner action, needs an access token); changing the email templates; PKCE.

## Assumptions
1. Only invitation and recovery links reach this page (self-signup is off), so the password page is the right destination for any
   fragment session.
2. The hosted redirect allow-list already accepts `/auth/callback` (the production invite on 2026-10-10 redirected there).

## Gate re-openers
Auth flow change (sensitive path `app/auth/**`) — approved by the owner for this fix. No schema, dependency or production write.

## Tasks
- [x] T1 Forward a fragment session from the link page to the password page — accept: unit test of the decision; e2e invite and
  recovery in the default shape land on the password page and finish in the workspace; error fragment shows the error page;
  `auth-links.spec.ts` unchanged and green.

## Implementation
- T1: `app/auth/callback/token.ts` gains `fragmentTarget(hash)`: a session (`access_token` + `refresh_token`) → the password page
  with the fragment intact; `error`/`error_code` → expired (`otp_expired`) or invalid; anything else → invalid. The link page
  (`app/auth/callback/page.tsx`) keeps its server path for `?token_hash`/`?code` and `?error`; with neither it renders
  `fragment-link.tsx`, which shows *Membuka tautan…* while it reads the fragment, then `location.replace()`s to `/atur-sandi#…`
  (nothing left in history) or shows the Bahasa error with *Kirim tautan baru*. `/atur-sandi` was unchanged: it already adopts a
  fragment session and strips it from the address bar. Tests: `tests/unit/auth-callback-fragment.test.ts`; a second test in
  `e2e/auth-links.spec.ts` follows invite and recovery links generated by the local auth server's admin API in the default
  shape, plus an expired fragment.

## Ship Notes
No migration, no env var. After deploy: people holding a default-template invite or reset email can use it as is. Someone who
already opened one and saw *Tautan tidak berlaku* (2026-10-10) can open the same link again only if it has not expired; otherwise
send a password reset from */login/lupa*. Still open (owner): push Buku's templates with `npm run auth:config -- --apply`, after
which new emails use the scanner-safe `token_hash` link again.
